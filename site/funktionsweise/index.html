Funktionsweise

Geräte finden sich über einen Raumcode. Danach versucht Comet Cast die Verbindungswege der Reihe nach.

1. Raumcode

Der Empfänger erzeugt einen Raumcode, auch als QR-Code. Der Sender gibt ihn ein. Der Code ist kurz; der Server bremst Raten durch Limits und zeitweise Sperren.

2. Verbindungswege, in dieser Reihenfolge

  1. Direkt. WebRTC zwischen den beiden Geräten.
  2. Über einen Server. Wenn direkt nicht geht: der Server einer Organisation mit TURN-Relay (und optional einem SFU).
  3. Eigenes WLAN. Wenn auch das nicht geht: das WLAN des Empfängers.

Die Reihenfolge ist der Plan. Gemessen ist bisher nur wenig: Verbindungen im lokalen Netz und ein TURN-Test auf einem einzigen Rechner. Über echte Netze, NAT oder zwischen zwei Geräten über TURN ist es UNCERTAIN.

Wie die App den Server findet

  1. MDM-Richtlinie
  2. DNS-SRV-Eintrag _cometcast._tcp
  3. Ankündigung des Anzeigegeräts
  4. Eingebaute Standardliste

Parallel läuft mDNS für die lokale Suche. Die Server-Suche in den Apps ist zum Teil noch nicht gebaut.

Was der Server tut

Der Server vermittelt nur: Räume und Signalisierung. Der offene Server speichert und leitet keine Bilder, Dateien oder Medien weiter. Der Bildschirm läuft direkt zwischen den Geräten oder, wenn nötig, über TURN. Mehr dazu auf der Seite Datenschutz & Selbst hosten.
