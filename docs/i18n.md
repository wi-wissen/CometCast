# Internationalisation (i18n)

The user interface is bilingual from the start: **German (`de`) and English (`en`)**. Everything else in the repository is English.

## Rules

1. **No hard-coded UI text.** Show text only through a translation key.
2. **Default language = system language.** If the system language is neither German nor English, English is used.
3. **The `en` and `de` key sets must be identical** in every app. A key that exists in one language must exist in the other.
4. Write translation values in plain, short sentences. Keep placeholders identical in both languages.

## Files per app

| App | Files |
| --- | --- |
| Web app | `apps/web/src/locales/en.json`, `apps/web/src/locales/de.json` (German "du", loaded); `de-sie.json` (formal set, not loaded, same keys) |
| Flutter app | `apps/flutter/lib/l10n/app_en.arb`, `apps/flutter/lib/l10n/app_de.arb` (German **du**, the shipped set). The formal **Sie** set is kept as `apps/flutter/lib/l10n/sie/app_de.arb`: not loaded; to switch, swap the two files (same keys and placeholders, checked by `tools/check-i18n.mjs` and `apps/flutter/test/l10n_sets_test.dart`). |
| Apple TV | `apps/apple-tv/Sources/CometCastTV/Localizable.xcstrings` and `InfoPlist.xcstrings` (each contains both languages; keys like `errors.rate_limited`; German uses "Sie") |

## Key naming

Web JSON: nested, written with dots (`home.sendScreen`). Flutter ARB: flat lower camel case (`homeSendScreen`), because ARB keys must be Dart identifiers. Apple TV: string catalog keys. In every case the first part is the screen or area and the rest names the item.

```
home.sendScreen
home.sendFile
receiver.waitingForSender
errors.roomCodeInvalid
```

Do not put the English text into the key. Do not reuse a key for a different meaning.

## Adding or changing a string

1. Add the key to the English file and to the German file in the same pull request.
2. Use the key in the code.
3. Run the check script: `node tools/check-i18n.mjs`. It compares the key sets of the `en` and `de` files and reports missing or extra keys.

If you cannot write the German text, add your best attempt and say so in the pull request, so a German speaker can review it.

## German: du is shipped, Sie is an alternate (Flutter)

The owner decided that the shipped German is informal ("du"). In the Flutter app `app_de.arb` holds the du strings and is the only German file that `flutter gen-l10n` reads (`l10n.yaml` points to `lib/l10n`). The formal set lives in `lib/l10n/sie/app_de.arb`; copy it over `app_de.arb` to ship "Sie". Only pronouns and verb endings differ. Strings that existed before the designed UI and addressed the reader formally were converted by changing only the pronoun and the verb form. (The Apple TV catalog and the web files are other implementers' areas.)
