# Implementation questions: Apple TV app

Asked by the Apple TV implementer (SwiftUI, `apps/apple-tv`). Each item: what was found, the options, and what was done meanwhile (the minimal neutral behaviour). Nothing here was decided by the implementer. The app was written without Xcode and has never been compiled (`docs/appletv.md`); the mockup was not opened beyond its canvas index, the pixel values come from the spec and from the built web display (`apps/web/src/styles/display.css` and the display components), which the spec names as the reference for the web.

## A. Fonts, copy, About

- **A1 Latin Extended glyphs.** The spec asks for Latin and Latin Extended (names of people). The Flutter assets hold the Latin Extended subset as separate files (`AtkinsonHyperlegibleNextExt-*.ttf`) whose PostScript names are identical to the main files (`AtkinsonHyperlegibleNext-Regular` and so on). Apple registers fonts by PostScript name, so two files with the same name would clash.
  - **Options:** (a) bundle only the five Latin files, characters outside them (for example `ł`, `ő`) fall back to the system font; (b) the designer or the font tooling provides one merged file per weight with Latin and Latin Extended; (c) bundle the Ext files under renamed PostScript names (changes the font files, the OFL asks for a different name when a font is modified).
  - **Did meanwhile:** (a). `apps/apple-tv/Resources/Fonts` has the five unmodified Latin files and the two OFL texts; `THIRD_PARTY_NOTICES.md` says so.
- **A2 Store line on the idle screen.** Spec 4.2: `idle.appLine` only when a store or download link exists, otherwise `idle.appLineWeb`. No store listing or download link of the presenter apps is known to this app (the web has `src/config/stores.ts`; there is no counterpart on tvOS).
  - **Options:** an Info.plist or build setting with the links; a fixed text.
  - **Did meanwhile:** `StoreLinks.exist = false` (`IdleView.swift`): the footer always reads `idle.appLineWeb` ("No download needed."). The branch for `idle.appLine` (including "`{dom}/app` written as `{dom}` where `{dom}` already ends in `/app`") is built.
- **A3 What About lists on Apple TV.** Spec 15.9 describes the content sources and names featured parts per platform only for "desktop builds", "where UxPlay is shipped" and "where the Office worker is shipped". Applying it as written to the Apple TV gives: featured = Cisco OpenH264, Atkinson Hyperlegible, PDFium Foxit font notice, Adobe CMap notice; all = every Rust crate and Flutter package heading and every npm row. Most of these are not linked into the tvOS binary (it is Swift with LiveKit WebRTC, no Rust, no Flutter, no npm). The parts that are in the tvOS binary (LiveKit WebRTC and the libraries inside it, swift-crypto only on Linux) are rows of tables in `THIRD_PARTY_NOTICES.md`, not sections, so the rules of 15.9 do not produce entries for them.
  - **Options:** (a) as the spec says, accepting entries that do not apply; (b) a per-platform filter and a section per tvOS component in `THIRD_PARTY_NOTICES.md` (needs the owner's or designer's list of what applies).
  - **Did meanwhile:** (a), with the platform qualifiers of the spec applied (Open Screen Library "on desktop builds", UxPlay, Office fonts left out). The parser takes the featured list as a parameter (`appleTvFeaturedNotices`), so (b) is a one-line change once the list exists.
- **A4 Names and subtitles of notice entries.** Spec 15.9 gives the subtitle rule (first non-empty line, at most 60 characters) for `####` entries only, and names two featured entries ("Cisco OpenH264", "Atkinson Hyperlegible"). For the other notice sections (PDFium Foxit, Adobe CMap) no display name is given.
  - **Did meanwhile:** the same subtitle rule for notice entries; the heading of the section as the name (`PDFium Foxit font notice (hayro-font)`, `Adobe CMap notice (hayro-cmap)`).
- **A5 Copy for two Apple-only media messages.** The link card for media (kept from the earlier app, spec 4.5 "Apple TV keeps its AVPlayer rules") has two messages that no spec table lists: http blocked by App Transport Security, and a file format AVPlayer cannot play. Both existed in German "Sie" form.
  - **Did meanwhile:** keys `receive.media.cleartext` and `receive.media.formatUnsupported`, the old English text, German du converted by pronoun only (no address form occurs, so du and Sie are equal). The i18n check lists `receive.media.cleartext` as the second known false alarm ("Sie" there means "it", the address).
- **A6 Media error retry.** The web media card has a "Try again" after an error. Spec 4.5 gives the tvOS focus row only as [Dismiss] or [Play, Dismiss].
  - **Did meanwhile:** after an error the card shows the error line and the row [Play, Dismiss]; Play starts again. No separate retry button.
- **A7 About button label in the dialog.** The About dialog's Close button: spec 15.9 says `settings.close` / `settings.closeRemote`. Used `settings.closeRemote` (TV), also in the licence viewer's top row.

## B. Behaviour the spec leaves open

- **B1 Which event shows which toast.** The spec lists the toast keys (`toast.joined`, `.allowed`, `.denied`, `.blocked`, `.expired`, `.withdrawn`, `.left`, `.sessionEnded`, `.openDisabled`) but not the triggers.
  - **Did meanwhile:** Yes, No, No and block show `allowed`, `denied`, `blocked` at once; the server's `join_request_cancelled` with `timeout` shows `expired`, with `left` or `cancelled` shows `withdrawn` (other reasons: no toast); a sender joining shows `joined` unless the host just allowed it (the allowed toast says it); the sender leaving shows `left` (the code stays); `room_ended` shows `sessionEnded`; the server refusing Open shows `openDisabled` once. Notices without copy (`blockListFull`, `lockedDiscarded`) are dismissed silently.
- **B2 Presenting while a transfer runs.** The web display treats "presenting" as content shown or a stream playing; a running image transfer alone does not count there, so its progress pill is not visible until something else is presenting. Spec 4.5 says the pill is shown "while presenting and while a transfer or opening runs".
  - **Did meanwhile:** on Apple TV a running transfer counts as presenting (black stage, the pill at the bottom), because otherwise the pill could never be seen for a first image. This also holds the wake lock during a transfer.
- **B3 A presentation that stops while the presenter stays joined.** The web display notices the end of a screen share through the removal of the stream's track. The Apple TV's `PeerSession` only reports the arrival of a video track; the screen share ending without `peer_left` is not detected, so Presenting stays on the last frame until the presenter leaves or the host presses End. Spec 4.5: "When the presenter stops, the display returns to Idle with the same code".
  - **Options:** observe the receiver or track end in the WebRTC wrapper (names of the LiveKit API not verified, so not written); poll the track's `readyState`.
  - **Did meanwhile:** nothing; it is a line in the device test plan (J-section additions, UI part).
- **B4 Statistics.** The earlier app showed an on-screen statistics badge on Play/Pause (needed by the device test plan). Play/Pause is now the Menu key (spec 7.1, native-apps.md 6.1) and the display shows nothing else (native-apps.md 18).
  - **Did meanwhile:** the statistics go to the log every 2 s in debug builds only (`stats video ...`), no screen, nothing in release builds.
- **B5 Wizard address pre-selection includes an announced box.** Spec 4.1 says the address is detected: DNS entry, then an in-house box found on the network, otherwise the default. The earlier core rule (`chooseRelay`) never pre-filled an announced server because any device in the network can announce one.
  - **Did meanwhile:** the wizard offers the merge order (policy, DNS, announcement, default), the first is shown with its source line (`sourceBox` for an announcement), and "Looks right" is the person's confirmation of it. A server chosen in the wizard counts as confirmed (spec N19: a native display gets no server from a link, so there is no relay confirmation page). Noted as a security observation for the designer: with an announcing device in the network the wizard's first suggestion can be that device.
- **B6 The box's IPv4 address (decision N40).** `idle.altAddress` needs the IPv4 address the announcement resolved to. `NWBrowser` results do not carry it in the TXT data the core reads.
  - **Did meanwhile:** the host name of the announced server is resolved with `getaddrinfo` (AF_INET) when the server came from an announcement and `{dom}` is a host name; the first IPv4 address is shown and used in the QR code. If resolution fails, no line and the QR keeps `{dom}`.
- **B7 Menu key at Idle and in the wizard.** Spec 7.1: Back on Idle "nothing (system may leave the app)", native-apps.md 5: "Apple TV: Menu leaves the app (tvOS rule)". On Apple TV the app does not handle Menu at Idle and wizard step 0 (the system leaves the app); on wizard steps 1 to 4 Menu goes back one step.
- **B8 Network return.** The reconnect schedule of spec 4.2 is built (1 s, 2 s, 3 s, every 4 s; busy 30 s; outdated never). The web additionally retries at once on the browser's `online` event. No path monitor on tvOS is used.
  - **Did meanwhile:** schedule only (at most 4 s until the next attempt).
- **B9 Name of a request without a usable name.** The machine used "Guest N" (English) for an empty name; spec 4.4 says `common.noName`.
  - **Did meanwhile:** `JoinRequest.unnamed` and `ReceiverState.peerUnnamed` mark it (the existing fixture test of `Guest 2` was extended), the screens show `common.noName`.
- **B10 End and Locked.** The earlier machine kept Locked across End; spec 4.3: "Locked is never stored: it lasts until End". The machine now starts the next session in the default mode (Open or Approval on, the last choice in Settings or setup). The existing test of `end_room` was changed to say so.
- **B11 Order of dialogs when two arrive.** A join request closes Settings (spec 4.3); a link card and a join request at the same time: the join request is shown, the link card appears after the last request.

## C. Focus and platform behaviour that can only be settled on a device

- **C1 Text fields on tvOS.** The wizard fields are SwiftUI `TextField`s in the plain style with the display's border and the spec's focus ring; whether tvOS draws its own focus look on top (even with `.focusEffectDisabled()`) is unknown. Listed in the device test plan.
- **C2 Licence viewer focus.** Left from the text pane is handled with `onMoveCommand` (back to the list); the focus engine may pick another row than the selected one.
- **C3 AVPlayerViewController in the link card** takes its own remote events; whether Back closes the card while playing is unknown.
- **C4 Safe area.** The canvas insets are derived from `GeometryProxy.safeAreaInsets` of a `GeometryReader` that ignores the safe area; the expected result at 1920 x 1080 points is top 30, bottom 30, sides 40 ref (native-apps.md 7), not verified.
- **C5 Transfer pill width.** The shortened file name is chosen with an assumed 8.2 ref px per character (15/700); the pill must stay on one line within 340. A measured value belongs in the device test plan.
- **C6 `lineSpacing`.** The type table's line heights are applied as `lineSpacing = size * (lineHeight - 1)` on top of the font's natural line height, which is assumed to be 1.0 em; Atkinson's real line metrics were not read.
